## 2. Sécurité produit (dApp / services / site)

### Déjà en place

* Montants **uniquement serveur** (PACK\_FIAT\_CENTS)
* Buyer = JWT/SIWX — jamais l’adresse URL seule
* IPN : payload signé seul, amount digits strict, idempotence duplicate
* Fail-closed sans credentials / sans HTTPS IPN
* LIA live flag indépendant (0 jusqu’à armement host)
* CORS configurable ; health sans secrets

### Gaps à traiter (priorité)

| Gap                                            | Surface      | Action                                                                          |
| ---------------------------------------------- | ------------ | ------------------------------------------------------------------------------- |
| CSP HTTP non observée ; CSP meta déjà présente | GitHub Pages | Auditer la CSP existante ; vérifier séparément la politique réellement servie   |
| X-Frame-Options non observé                    | Pages        | Configuration HTTP sur une couche maîtrisée ; une balise meta ne l’applique pas |
| X-Content-Type-Options non observé             | Pages        | Servir `nosniff` comme véritable entête HTTP, puis contrôler la réponse         |
| Referrer-Policy HTTP non observée              | Pages        | Définir une politique de référent adaptée, puis contrôler HTTP et HTML          |
| Rate limit checkout                            | API          | plafond / IP / buyer (Render ou middleware)                                     |
| Monitoring IPN                                 | ops          | alerte bad\_signature / amount\_mismatch                                        |
| Smoke prod réel                                | métier       | 1× Sentinel live + order\_id                                                    |
| LIA live                                       | Vellum       | `LIA_LIVE_TRADING=1` + bootstrap signé                                          |

### Précisions issues du contrôle complémentaire

Le HTML public contient déjà une balise `Content-Security-Policy`. Lors du GET effectué pour cette révision, aucun entête HTTP CSP, X-Frame-Options, X-Content-Type-Options ou Referrer-Policy n’a été observé. Une étape de build ou un fichier statique ne prouve pas la configuration HTTP du serveur Pages : vérifier la réponse servie après tout changement. Pour des entêtes maîtrisés, évaluer une couche d’hébergement ou un proxy/CDN configurable, sans changer le domaine ni déployer cette migration dans ce lot.

`frame-ancestors` n’est pas pris en charge dans une CSP meta ; X-Frame-Options meta n’a aucun effet. Références : [MDN frame-ancestors](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors), [MDN X-Frame-Options](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Frame-Options).

`lia_live_trading: 0` dans le health concerne cette API. L’état du host Vellum doit être vérifié indépendamment ; ne pas déduire son état de l’API.

### Interdits maintenus

* PEM / mnemonic dans git ou logs
* Confiance `?paid=` navigateur
* Double mint sur IPN rejoué
* `LIA_LIVE_TRADING=1` sans gates AND
