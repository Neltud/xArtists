# Audit renforcé — 28 octobre 2026

### Verdict et périmètre

**Ouverture marchande et trading live : NO-GO.** Le site public sert LIA paper, Paybox désactivé et une URL d'API vide. Les sondes exposent des défauts ; aucune exploitation distante ni mouvement de fonds provoqué par ces tests n'est constaté.

Référence Git : `352de2dc8abcba08885506e4f5b44e4c67cc5c05`. PR #200 ouverte : nouveau head `21e043d33644da04facab8915ea55827f056d122`, relu avant livraison du kit. Le head `e206da7…` est historique. PR #201 de release également ouverte. Toute évolution ultérieure exige de relire les SHA.

Les preuves brutes et scripts sont dans `artifacts/security-readiness-2026-10-28/`. Les sondes de défaut terminent à 1 : ne pas les rendre vertes en supprimant les assertions. Les lectures VM sont sans signature, frais, mint, burn ou fonction de mutation.

### Constats et critères de clôture

Les P0 sont des blocages de lancement. Un défaut de code non exposé est distingué d'une faille distante active.

#### S01 — P0 sandbox : PR #200 partiellement corrigée, toujours non validable

Le nouveau head `21e043d33644da04facab8915ea55827f056d122` est relu après les changements de Grok. La course du store fichier est corrigée dans la sonde : **trois commandes concurrentes sur trois conservées**, exit 0. Le code garde le verrou pendant toute la section async et utilise une attente non bloquante. Le défaut historique « une commande sur trois » ne décrit donc plus ce head.

`rejectUnauthorized:true` est désormais configuré par défaut, `pg@8.13.1` est déclaré et `npm ci` rétabli dans le workflow. Ces modifications sont vérifiées dans les fichiers ; aucun test de connexion TLS/Postgres réelle n'a encore été fait.

**Blocage actuel CI : installation, pas étape de test.** Le run [40653257808](https://github.com/Neltud/xArtists/actions/runs/40653257808), job `122698104925`, échoue sur `Install API dependencies` avec EUSAGE. Le lockfile ne contient que la racine, sans entrées de dépendances ; sdk-core, pg et les transitives y manquent malgré les messages de commit annonçant un lock complet. Les tests API sont ignorés dans ce run.

Dans une copie isolée du nouveau head, en réutilisant le cache SDK pour examiner la logique indépendamment de ce blocage d'installation : **61 tests, 59 succès, deux échecs**, exit 1. Ils restent dans `paybox_v2.test.mjs:154` et `:160` : appels sans `await` et `assert.throws` sur une Promise. Les trois cas correspondants de `paybox_orders` ont été adaptés. Cette exécution locale ne valide ni `npm ci` ni Postgres.

Historique conservé pour comparaison : à `e206da7…`, CI 55/60 et perte de deux commandes sur trois. Les reproductions historiques restent étiquetées comme telles ; elles ne doivent pas servir à nier les corrections du nouveau head.

**Clôture restante :** vrai lock généré et `npm ci` propre, deux tests v2 async corrigés sans affaiblir leurs assertions, CI verte au head courant, puis Postgres réel (doublons, provider TX réutilisée, panne, concurrence, redémarrage/restauration). DB indisponible = fermé sans repli fichier éphémère ; health doit tester le backend requis. Vérifier la configuration SSL effective de l'URI et les certificats.

Preuves actuelles : `PR200_LATEST_REVIEW.json`, `PR200_LATEST_API.portable.tap`, `PR200_LATEST_FILE_CONCURRENCY.log`, `pr200/orders-latest.mjs` SHA-256 `6454b7821c024cad822315628ee0877dcdf367486f165d729ee9373a2ec7a4df`. Source historique : `orders-under-review.mjs`, SHA-256 `5eb693ea8da02ee8c0b685f07cd4bf92888295037f9b9c23c7fc2e74f2c0b747`.

#### S02 — P0 avant autonomie : corruption de l'état de risque

`lia/guardian/risk_enforcer.py:37–53` ignore une erreur de lecture et retourne pertes/compteurs nuls avec `halt:false`. Reproduction sur un fichier temporaire corrompu : l'arrêt attendu n'est pas imposé. La sonde n'appelle ni `enforce`, ni signataire, ni broadcast ; elle prouve une perte d'état, pas un trade.

Le routeur reçoit `daily_spent_usd` de son appelant : ce contrôle ne constitue pas un budget global durable. Les montants de risque doivent aussi être recalculés depuis la transaction et le devis, pas seulement crus comme métadonnées.

**Clôture :** corruption/panne = arrêt et conservation de preuve ; écritures et réservations atomiques avant signature ; rapprochement après confirmation ; tests concurrence/redémarrage. Caps LIA 15 USD/ordre et 40 USD/jour distincts des achats clients.

#### S03 — P0 fonds publics : propriétaire unique et upgrades

Les dix comptes sont upgradeables par un même propriétaire on-chain sans codeHash. Aucun build reproductible ni preuve de garde à plusieurs personnes n'est fourni. Égalité hash observé/référence n'est pas égalité source/WASM prouvée.

Les mappers métier `owner` et l'owner du compte blockchain sont des pouvoirs distincts. Dans `agents-marketplace`, `transferOwnership`/`acceptOwnership` modifient le mapper ; cela n'atteste pas un transfert du pouvoir d'upgrade du compte.

**Clôture :** manifeste réseau/adresse/commit/toolchain/WASM/hash calculé/ABI/owners ; garde et approbation à plusieurs personnes, délai d'upgrade adapté, récupération et pause éprouvées. L'adresse owner, LIA Ops et la garde d'un fichier PEM ne sont pas équivalentes.

#### S04 — P0 processus : contrôles GitHub non attestés

Le ruleset lisible `13907957` bloque suppression et non-fast-forward et ajoute Copilot. Il ne contient ni revue humaine obligatoire ni statut requis. Les protections historiques répondent 403 : leur absence n'est pas démontrée.

Des workflows manuels utilisent `SC_DEPLOYER_PEM` ou `LIA_WALLET_PEM` sans `environment:` visible. Une confirmation textuelle de dispatch ne prouve pas un second approbateur. Les secrets réellement installés ne sont pas inspectés.

**Clôture :** preuves opérateur des protections effectives, revue humaine des chemins financiers/workflows, checks au SHA courant, bypass bot réduits, signature isolée des builds et contenus d'agents. Vellum doit consommer une version approuvée épinglée, pas un `main` mouvant avec une clé.

#### S05 — P0 de preuve : « AI Security Audit » peut ne rien auditer

`scripts/ci_ai_pr_review.py` retourne 0 si clé absente ou appel OpenAI échoué. Exécution locale sans clé : « review skip », exit 0. Le vert ne prouve aucune revue. Le workflow exécute un script de PR avec variables de secret et token de commentaire : une PR interne modifiant ce script traverse une frontière de confiance. Les forks ont des restrictions distinctes ; aucune exfiltration tentée.

**Clôture :** contrôles déterministes bloquants indépendants du modèle, statut SKIPPED explicite et aucun code non approuvé exécuté avec secrets/écriture. La revue IA reste consultative. Budget 0 € : aucun appel facturable ajouté.

#### S06 — P0 de triage : dépendances frontend

`npm audit --omit=dev --json --ignore-scripts`, sans `fix` : **30 paquets signalés frontend : 1 critique, 5 élevés, 17 modérés, 7 faibles**. API : deux paquets signalés modérés, `sdk-core` et `uuid`, pour une chaîne transitive commune. Ce ne sont pas des nombres de failles indépendantes ni une preuve d'exploitation.

Le lock contient `protobufjs` 7.2.6 et 7.4.0. Les avis mainteneur décrivent notamment de la génération de code à partir de schémas contrôlés par un attaquant. L'audit n'a pas démontré que la dapp accepte ces schémas. Autres alertes : `ws`, `qs`, providers et WalletConnect.

**Clôture :** nomenclature du build, joignabilité par advisory, mise à jour compatible ou acceptation motivée, puis recettes wallet/SIWX/signature. Aucun `npm audit fix --force` ni rétrogradation SDK aveugle.

Preuves : `NPM_AUDIT_FRONT.json`, `NPM_AUDIT_API.json`. Avis primaire : [protobuf définitions non fiables](https://github.com/protobufjs/protobuf.js/security/advisories/GHSA-xq3m-2v4x-88gg), [toObject](https://github.com/protobufjs/protobuf.js/security/advisories/GHSA-66ff-xgx4-vchm).

#### S07 — P1 : cache runtime encore permissif

Le gate en **ET** et la fermeture après refresh échoué sont conservés. Sondes supplémentaires : timestamp futur accepté, `jobsFp` absent accepté, ancien positif utilisable pendant un refresh lent. Aucun timeout de `fetch`, et publication seulement après tout le lot.

**Clôture :** invalidation des positifs au début, délai borné, empreinte exacte, dates futures/non finies rejetées ; tests appel suspendu et course entre générations. Le cache client n'est jamais une autorité serveur ou contractuelle.

#### S08 — P0 commercial / P1 code : devis et prix

SC : 10 / 5 / 2,5 EGLD ; ancre client : 110 / 75 / 50 EUR. Le calculateur respecte la parité pour le taux fourni, mais ce taux vient du client. Aucun devis signé, durable, lié au buyer/rail/commande et consommé par le paiement.

`isQuoteExpired({expires_at:'not-a-date'})` retourne `false`. Aucun paiement réel utilisant cette fonction n'a été démontré.

**Clôture :** taux serveur vérifié/frais, devis signé à usage unique, montants atomiques entiers, wallet/destinataire/actif/chaîne/prix/expiration liés, adaptation contrôlée du rail SC. Voir [prix et livraison](pricing-delivery.md).

#### S09 — P0 paiement réel : paiement ≠ livraison ≠ accès

L'IPN produit actuellement `delivery: simulated`. Le fichier n'est pas durable sur Render Free ; Postgres n'est pas validé. `buyPack` livre à l'appelant et ne fournit pas automatiquement un relayer fiat livrant au véritable acheteur.

**Clôture :** commande durable → PSP vérifié/dédupliqué → intention de livraison liée buyer → NFT confirmé sur la bonne chaîne → droits activés. Pannes entre étapes, rapprochement et refunds testés. Sans wallet : identité et droits séparés restent à implémenter ; pas de FULL parce que LIA détient un NFT.

#### S10 — P1 avant exposition : Vellum et Guardian HTTP

Le proxy `services/vellum-8008-proxy/main.py` accepte workflow/inputs du client sans auth applicative, avec CORS permissif par défaut et sans budget/débit visible. Exposé avec une clé, il permettrait l'usage non autorisé de ressources ; l'exposition n'est pas attestée par le bundle.

Guardian HTTP accepte des intentions non authentifiées, conserve un audit en mémoire et expose `/audit/recent`. Ce module ne diffuse pas de TX. Son plafond par défaut ne prouve pas les caps USD de l'exécuteur.

**Clôture :** rester non exposé avant authz identité/action, allowlist workflow serveur, bornes taille/débit/budget, journaux bornés ; aucune clé dans `VITE_*`. CORS n'est pas une auth. Grok/MCP doit fournir des données validées, sans capacité de commande implicite.

#### S11 — P1 : sessions et robustesse API

MAC, algorithme et `exp` sont vérifiés. Des JWT signés avec une clé de fixture montrent que `iss` et `nbf` ne sont pas contrôlés ; ce n'est pas une falsification sans clé. Ajouter les attentes de claims et l'audience si plusieurs composants consomment le token.

Le JWT en `sessionStorage` reste lisible par les scripts de l'origine : risque en cas de XSS, sans XSS prouvée ici. Préparer mémoire courte durée ou BFF/cookie protégé avec stratégie CSRF adaptée. Compléter limites de débit, timeouts et caches bornés sur les endpoints exposés.

#### S12 — P1 : arrêt et exploitation

`isPayable=false` ne démontre ni pause des endpoints contractuels ni fermeture HTTP. Une UI fermée ne révoque pas les appels directs. `isPaused` échoue pour deux adresses : méthode de vérification et ABI doivent être propres à chaque contrat.

**Clôture :** arrêt exécuteurs, fermeture chemins d'ordre, conservation des journaux, autorité de pause, reprise à deux personnes, tests restauration et exercice de pause. Rotation, upgrade et pause sont des actions séparées soumises à GO opérateur.

#### S13 — P1 : publication et coût

Quarante workflows sont présents ; plusieurs cron et le snapshot Pages écrivent directement dans `main`. Les actions inspectées utilisent des tags mobiles. Séparer données générées et sources relues, limiter les permissions par job, épingler/verrouiller les dépendances d'actions.

Le gratuit reste un pilote à quotas, pas une preuve de continuité pour les IPN. Aucun maintien artificiel en éveil, ressource payante ou modèle facturable autorisé. Documenter suspension, retry PSP, rapprochement et opérateur.
